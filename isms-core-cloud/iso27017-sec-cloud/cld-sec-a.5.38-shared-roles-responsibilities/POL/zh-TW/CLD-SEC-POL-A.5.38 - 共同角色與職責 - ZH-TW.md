## 執行摘要

本政策訂定[組織]如何依 ISO/IEC 27017:2026 條款 5.38，就其參與的每一段雲端運算關係，分配、文件化、溝通並落實資訊安全角色與職責。

**範圍**：[組織]所參與的所有雲端服務 — 無論是作為取用第三方雲端服務的雲端服務客戶（CSC），或作為向其自有客戶提供雲端服務的雲端服務供應商（CSP）。當[組織]同時兼具兩種角色時（例如在 CSP 的基礎架構上建置並提供自有雲端服務），本政策對各角色分別適用。涵蓋 IaaS、PaaS 與 SaaS 模式下的公有、私有、混合及多雲部署，包括職責沿供應鏈層轉的分層關係。

**延伸控制說明**：ISO/IEC 27017:2026 條款 5.38 是該標準第二版所導入四項雲端專屬「CLD」延伸控制之一（另三項為 5.39、8.35 與 8.36），在 ISO/IEC 27002:2022 或 ISO/IEC 27001:2022 附錄 A 中並無直接對應項。[組織]將其作為以 ISO/IEC 27001:2022 為基礎之 ISMS 的資訊性延伸予以落實，與 ISO/IEC 27017:2026 本身對這些控制的定位一致。

**核心原則**：雲端運算的資訊安全從不單屬 CSP 或單屬 CSC 的責任 — 它是共同承擔的，且該共同分配必須先經雙方識別、文件化、溝通並落實，方足以信賴。該分配若有模糊不明，應視為資訊安全風險予以處理，而非留待日後才解決的形式手續。

# 範圍與適用性

## ISO/IEC 27017:2026 — 條款 5.38

**控制敘述（ISO/IEC 27017:2026, 5.38）：**
> 「使用雲端服務時，共同資訊安全角色的職責應分配予已識別之各方，並由 CSC 與 CSP 雙方予以文件化、溝通及落實。」

**目的（ISO/IEC 27017:2026, 5.38）：**
> 「闡明 CSC 與 CSP 之間就資訊安全管理之共同角色與職責的關係。」

## 適用性

本政策適用於：

- [組織]作為雲端服務客戶（CSC）所取用的所有雲端服務，涵蓋所有部署模式（公有、私有、混合、多雲）與服務模式（IaaS、PaaS、SaaS）
- [組織]作為雲端服務供應商（CSP）向其自有客戶提供的所有雲端服務
- 所有代表[組織]從事雲端服務選擇、組態、維運或交付的人員

## 法規與標準架構

ISO/IEC 27017:2026 是 ISO/IEC 27002:2022 的資訊性延伸，就組織已在其以 ISO/IEC 27001:2022 為基礎之 ISMS 下落實的控制措施，提供雲端專屬指引。條款 5.38 不對應 ISO/IEC 27002:2022 中的任何編號控制措施；它是 2026 年第二版新導入的控制，主題上最接近 ISO/IEC 27001:2022 附錄 A 控制 5.2 的角色與職責義務，並與其一併落實。

# 政策敘述：共同角色與職責（5.38）

## 身為雲端服務客戶（CSC）的義務

當[組織]擔任雲端服務客戶時，[組織]應：

- 於服務選擇與導入階段，取得 CSP 所提出的資訊安全角色與職責分配，並在服務投入正式使用前，對照[組織]自身能力與風險胃納進行審查
- 確保[組織]與 CSP 雙方的資訊安全角色與職責載明於書面協議 — 而非僅仰賴 CSP 的公開文件，因其可能未經通知即行變更
- 於 CSP 的客戶支援單位中指定並維持一名具名聯絡窗口，供資訊安全事項呈報之用
- 向 CSP 索取其資訊安全能力的相關資訊 — 包括身分驗證、密碼學、備份與日誌 — 並於 CSP 自身揭露不足時，採用第三方或獨立機構框架（例如 ISO/IEC 27001 驗證範圍、SOC 2 報告、CSA STAR 登錄）補強該等資訊
- 將 CSP 所提分配與[組織]履行自身受分配職責之能力間的任何缺口，評鑑為資訊安全風險；若無法於上線前弭平，應納入[組織]已文件化的風險評鑑與處理程序
- 透過組織的資訊安全認知方案（參見 ISMS-POL-A.6.3），並將之納入雲端架構審查作業，使員工持續知悉其使用之雲端服務的議定分配

## 身為雲端服務供應商（CSP）的義務

當[組織]擔任雲端服務供應商時，[組織]應：

- 界定並文件化其 CSC、[組織]本身，以及[組織]自有供應商或雲端服務夥伴各自應落實的資訊安全角色與職責分配
- 於簽約前及任何重大變更後，向潛在及既有 CSC 溝通該分配 — 透過服務協議、面向客戶的安全文件或導入資料，並視服務性質擇用
- 就資訊安全議題與各 CSC 建立並維持關係，包括於協議中載明所定的呈報路徑
- 向 CSC 提供該雲端服務的資訊安全能力，以及[組織]已採取之資訊安全措施的相關資訊，其清晰程度應足以讓 CSC 適當理解 — 並於有助傳達該等資訊時，採用公認的第三方或獨立機構框架
- 當服務依賴上游 CSP（分層或供應鏈關係）時，評鑑並文件化職責如何層轉，並確保其與[組織]依 CLD-SEC-POL-A.5.39 與其雲端服務夥伴所訂協議一致
- 將 CSC 提出或內部發現、關於職責分配的爭議或持續存在的模糊不明，視為須呈報的資訊安全事件，而非例行支援查詢

## 共同分配原則

雲端運算中的角色與職責通常由 CSC 與 CSP 分擔。[組織]以任一身分分配角色與職責時，應考量 CSC 的資料及應用系統 — 即[組織]（作為 CSP）為其保管者者，或[組織]（作為 CSC）於 CSP 技術保管之下仍負最終責任者。

## 共同責任矩陣 — 最低內容

本政策適用範圍內的每一段雲端服務關係，均應有最新的共同責任矩陣支持。該矩陣至少應就每個責任領域（例如身分驗證、密碼學、備份、日誌、修補、網路分段）記錄：該責任分配予何方（CSC、CSP 或共同）；各方為履行其負責部分所須採取的行動；[組織]是否已確認其能履行自身受分配的部分；以及最近一次審查日期。完整綱要載於 CLD-SEC-IMP-A.5.38-TG 第 1 節。新的雲端服務關係投入正式使用前，該矩陣應由雲端安全經理審查，其後至少每年審查一次。

# 角色與職責

| 角色 | 職責 |
|------|-----------------|
| **CISO** | 為 CLD-SEC-POL-A.5.38 的擁有者；核可策略性或高風險雲端服務關係的共同責任分配；將未解決的分配缺口呈報高階管理層；於管理審查時檢視政策有效性 |
| **雲端安全經理** | 就所取用的服務（CSC 角色），審查 CSP 提供的角色／職責文件；就所提供之服務（CSP 角色），建立並維護發布予 CSC 的角色／職責文件；維護每一段有效關係的共同責任矩陣；向 CISO 報告分配缺口與矩陣涵蓋率指標 |
| **法務／法遵主管** | 確保議定的角色與職責分配反映於與各 CSC 或 CSP 相對方所訂的書面協議中 |
| **雲端服務交付／工程** | 落實對應於[組織]受分配職責的技術控制措施；呈報任何[組織]無法履行的職責 |
| **全體人員** | 僅於分配予其職能的角色與職責範圍內作業；向雲端安全經理報告共同責任分配上的任何模糊不明 |

# 監控與指標

雲端安全經理至少每季向 CISO 報告下列事項：

- 有效雲端服務關係（CSC 與 CSP 角色）中，具備最新且經審查之共同責任矩陣的比例
- 已識別並呈報進入風險評鑑與處理程序的分配缺口數量及其處理狀態
- CSC 或內部團隊提出之職責分配爭議或模糊不明的件數

本政策有效性於管理審查時評估，並於任何與雲端相關、且共同責任分配與根因有關的安全事件後評估。

# 查核考量

查核人員驗證 CLD-SEC-POL-A.5.38 遵循情形時，應可預期見到：

- 每一段有效雲端服務關係（CSC 或 CSP 角色）均有一份共同責任矩陣，且符合上述最低內容要求
- 書面協議明示而非暗示資訊安全角色與職責的分配
- 有證據顯示[組織]於擔任 CSC 時，係主動審查並確認 CSP 所提分配，而非逕予接受
- 有證據顯示[組織]於擔任 CSP 時，係主動文件化並向 CSC 溝通其分配，而非等候 CSC 索取
- 有證據顯示分配缺口已納入風險評鑑與處理程序，而非僅予註記後懸置
- 每季監控指標顯示對矩陣涵蓋率的主動監督，而非一次性作業
