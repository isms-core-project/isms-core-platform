## 本指南目的

本指南提供在 ISO/IEC 27017:2026 條款 5.38 之下，將共同資訊安全角色與職責予以文件化所需的**技術結構、綱要與範本**。內容涵蓋：

- 共同責任矩陣綱要（CSC 與 CSP 兩種角色均使用）
- 面向 CSC 的能力說明文件範本（CSP 角色）
- 責任分配缺口紀錄綱要

**適用對象**：CISO、雲端安全經理、雲端工程。

---

## 1. 共同責任矩陣綱要

每一段雲端服務關係建立一份矩陣。由雲端安全經理維護。

| 欄位 | 類型 | 說明 |
|-------|------|-------------|
| `service_id` | 字串（唯一） | 內部參照：`CSV-YYYY-NNN` |
| `service_name` | 字串 | 雲端服務的名稱 |
| `counterparty_name` | 字串 | CSP 的名稱（若[組織]為 CSC）或 CSC 的名稱（若[組織]為 CSP） |
| `organisation_role` | 列舉 | CSC／CSP／兩者 |
| `service_model` | 列舉 | IaaS／PaaS／SaaS |
| `shared_responsibility_model_ref` | 字串 | 所依據之已發布共同責任模型的參照／版本 |
| `responsibility_area` | 字串 | 例如「身分驗證」、「密碼學」、「備份」、「日誌」、「修補」、「網路分段」 |
| `allocated_to` | 列舉 | CSC／CSP／共同 |
| `csc_action_required` | 文字 | CSC 為履行其負責部分所須採取的行動（若為共同或分配予 CSC） |
| `csp_action_required` | 文字 | CSP 為履行其負責部分所須採取的行動（若為共同或分配予 CSP） |
| `fulfilment_confirmed` | 布林值 | [組織]是否已確認其能夠／確實履行所分配的部分 |
| `last_reviewed_date` | 日期 | 此責任領域上次審查的日期 |
| `next_review_date` | 日期 | 下次排定審查的日期 |
| `notes` | 文字 | 例外、補償性控制措施或升級通報參照 |

## 3. 責任分配缺口紀錄綱要

記錄共同責任矩陣中發現的任何缺口及其處理結果。

| 欄位 | 類型 | 說明 |
|-------|------|-------------|
| `gap_id` | 字串（唯一） | 內部參照：`ARG-YYYY-NNN` |
| `service_id` | 字串 | 共同責任矩陣項目的參照 |
| `identified_date` | 日期 | 發現缺口的日期 |
| `identified_by` | 字串 | 發現缺口者的姓名／角色 |
| `gap_description` | 文字 | 未分配或無法履行之責任的說明 |
| `identification_source` | 列舉 | 上線審查／年度審查／事件／CSP 或 CSC 通知 |
| `escalated_to_ciso` | 布林值 | 是否已升級通報至 CISO |
| `resolution_type` | 列舉 | 補償性控制措施／合約修訂／重新評估服務／接受風險 |
| `resolution_description` | 文字 | 缺口如何處理的說明 |
| `resolution_date` | 日期 | 缺口結案的日期 |
| `signed_off_by` | 字串 | 核准結案者的姓名／角色 |
