🌍 Mehrjurisdiktionelles Richtlinien-Rendering

ISMS CORE-Richtlinien passen sich zur Anforderungszeit an 7 regulatorische Rechtssysteme an — sie ersetzen Schweizer-Recht-Referenzen durch die korrekten nationalen Behördennamen, Datenschutzgesetze und Finanzsektor-Aufsichtsbehörden für jedes Land. Ein Richtlinien-Set. Keine Duplikate. Kein Wartungsaufwand.

Lokalisierung vs. Übersetzungen — Zwei getrennte Schichten

ISMS CORE bietet beides — sie sind komplementär, nicht dasselbe.

🌍

Länderlokalisierung (diese Seite)

Richtlinien werden einmal auf Englisch verfasst. Zur Render-Zeit werden Schweizer-Recht-Tokens (PFPDT, nLPD, FINMA…) durch die korrekten nationalen Entsprechungen für das Land der Organisation ersetzt. Keine doppelten Richtliniendateien — eine einzige Quelle der Wahrheit.

🌐

Mehrsprachige Übersetzungen

Alle Richtlinien sind auch als vollständig übersetzte Dokumente in Französisch, Deutsch und Italienisch verfügbar — für alle vier Produkte (Framework, Operational, Privacy, Cloud). Dies sind vorgeschriebene, QA-geprüfte Dokumente, keine maschinellen Übersetzungen.

Was substituiert wird

Jede Länderkonfiguration definiert eine Token-Map. Wenn eine Richtlinie angefordert wird, wendet die Plattform Substitutionen in der Reihenfolge an — längste Übereinstimmung zuerst, sodass zusammengesetzte Begriffe wie "revDSG" vor kürzeren Teilstrings ersetzt werden.

Vollständige Substitutions-Maps sind in Länder-YAML-Konfigurationen definiert, die zum Build-Zeitpunkt in das Docker-Image eingebettet sind. Tokens decken auch ab: nationale Verpflichtungsreferenzen, sektorale Regulierungen, administrative Namen und verfahrensrechtliche Begriffe.

Wie es funktioniert

Die Rendering-Pipeline ist rein additiv — Quell-Richtliniendateien werden niemals modifiziert.

1. AnforderungRichtlinie für Org abgerufen
→
2. Nachschlagenorg.country-Feld gelesen
→
3. Konfiguration ladenLänderkonfiguration geladen (LRU-gecacht)
→
4. RendernToken-Substitution angewendet (längste zuerst)
→
5. AntwortLänderspezifische Richtlinie zurückgegeben
Warum keine Duplikate? Das Klonen von Richtlinien pro Land schafft ein Wartungsdesaster — 250+ Dokumente × 7 Länder × 4+ Sprachen ergibt 7'000+ Dateien, die alle aktualisiert werden müssen, wenn sich eine Regulierung ändert. ISMS CORE löst dies mit einem Single-Source-of-Truth-Ansatz: Die Basis-Richtlinie ist massgeblich, und die Länderkonfiguration ist ein dünner Overlay. Aktualisieren Sie eine Konfigurationsdatei, alle betroffenen Richtlinien werden bei der nächsten Anforderung sofort aktualisiert.

Landeseinstellung für eine Organisation

Das Land wird pro Organisation (Mandant) von einem Super Admin festgelegt. Alle an diese Organisation gelieferten Richtlinien werden mit den korrekten Jurisdiktions-Tokens gerendert.

  1. Navigieren Sie zu Organisationen im Admin-Panel
  2. Bearbeiten Sie die Organisation und wählen Sie Land / Regulatorisches Rechtssystem
  3. Speichern — alle nachfolgenden Richtlinien-Renderings verwenden die neue Länderkonfiguration
  4. Kein Neustart oder Rebuild erforderlich — Konfigurationen sind zum Build-Zeitpunkt in das Docker-Image eingebettet und beim ersten Zugriff im Speicher zwischengespeichert

Zugehörige Compliance-Assessment-Module

Jede Jurisdiktion verfügt über ein oder mehrere zweckgebaute Assessment-Module in der Plattform. Verwenden Sie die Länderlokalisierung + das passende Modul zusammen für die genaueste Compliance-Positionierungsansicht.
