🌍 Rendering di Politiche Multi-Giurisdizionale

Le politiche ISMS CORE si adattano a 7 giurisdizioni normative al momento della richiesta — sostituendo i riferimenti al diritto svizzero con i nomi corretti delle autorità nazionali, le leggi sulla protezione dei dati e gli organismi del settore finanziario per ogni paese. Un set di politiche. Nessun clone. Nessun onere di manutenzione.

Localizzazione e traduzioni — Due livelli distinti

ISMS CORE fornisce entrambi — sono complementari, non la stessa cosa.

🌍

Localizzazione per paese (questa pagina)

Le politiche vengono scritte una volta in inglese. Al momento del rendering, i token del diritto svizzero (PFPDT, nLPD, FINMA…) vengono sostituiti con gli equivalenti nazionali corretti per il paese dell'organizzazione. Nessun file di politica duplicato — un'unica fonte di verità.

🌐

Traduzioni multilingue

Tutte le politiche sono disponibili anche come documenti completamente tradotti in francese, tedesco e italiano — per tutti e quattro i prodotti (Framework, Operational, Privacy, Cloud). Sono documenti pre-scritti e verificati dalla QA, non traduzioni automatiche.

Cosa viene sostituito

Ogni configurazione paese definisce una mappa di token. Quando viene richiesta una politica, la piattaforma applica le sostituzioni in ordine — corrispondenza più lunga prima, in modo che termini composti come "revDSG" vengano sostituiti prima delle sottostringhe più brevi.

Le mappe di sostituzione complete sono definite nelle configurazioni YAML paese integrate nell'immagine Docker al momento della build. I token coprono anche: riferimenti agli obblighi nazionali, normative settoriali, nomi amministrativi e termini procedurali.

Come funziona

La pipeline di rendering è puramente additiva — i file di politica sorgente non vengono mai modificati.

Pipeline di rendering al momento della richiesta

1. RichiestaPolitica recuperata per l'org
→
2. RicercaCampo org.country letto
→
3. Caricamento configConfig paese caricata (cache LRU)
→
4. RenderingSostituzione token applicata (più lungo prima)
→
5. RispostaPolitica specifica per paese restituita
Perché nessun clone? Clonare le politiche per paese crea un incubo di manutenzione — 250+ documenti × 7 paesi × 4+ lingue = 7.000+ file che devono essere tutti aggiornati quando cambia una normativa. ISMS CORE risolve questo con un approccio a fonte unica di verità: la politica di base è autorevole, e la configurazione del paese è un sottile strato sovrapposto. Aggiorna un file di configurazione, tutte le politiche interessate vengono aggiornate istantaneamente alla prossima richiesta.

Impostazione del paese di un'organizzazione

Il paese è impostato per organizzazione (tenant) da un super admin. Tutte le politiche servite a quell'organizzazione vengono rese con i token di giurisdizione corretti.

  1. Naviga verso Organizzazioni nel pannello di amministrazione
  2. Modifica l'organizzazione e seleziona Paese / Giurisdizione normativa
  3. Salva — tutti i rendering di politiche successivi utilizzano la nuova configurazione paese
  4. Nessun riavvio o rebuild richiesto — le configurazioni sono integrate nell'immagine Docker al momento della build e memorizzate nella cache in memoria al primo accesso

Moduli di valutazione della conformità associati

Ogni giurisdizione dispone di uno o più moduli di valutazione dedicati nella piattaforma. Usa la localizzazione per paese + il modulo corrispondente insieme per la visione più accurata della postura di conformità.
