🌍 Multi-Jurisdiction Policy Rendering

ISMS CORE policies adapt to 7 regulatory jurisdictions at request time — replacing Swiss-law references with the correct national authority names, data protection laws, and financial sector bodies for each country. One policy set. No clones. No maintenance overhead.

Localisation vs. Translations — Two Distinct Layers

ISMS CORE provides both — they are complementary, not the same thing.

🌍

Country Localisation (this page)

Policies are written once in English. At render time, Swiss-law tokens (PFPDT, nLPD, FINMA…) are replaced with the correct national equivalents for the organisation's country. No duplicate policy files — one source of truth.

🌐

Multilingual Translations

All policies are also available as fully translated documents in French, German, and Italian — across all four products (Framework, Operational, Privacy, Cloud). These are pre-written, QA-verified documents, not machine translations.

What Gets Substituted

Each country config defines a token map. When a policy is requested, the platform applies substitutions in order — longest match first, so compound terms like "revDSG" are replaced before shorter substrings.

Full substitution maps are defined in country YAML configs baked into the Docker image at build time. Tokens also cover: national obligation references, sectoral regulations, administrative names, and procedural terms.

How It Works

The rendering pipeline is purely additive — source policy files are never modified.

Request-time rendering pipeline

1. Request Policy fetched for org
→
2. Lookup org.country field read
→
3. Load config Country YAML loaded (LRU-cached)
→
4. Render Token substitution applied (longest-first)
→
5. Response Country-specific policy returned
Why no clones? Cloning policies per country creates a maintenance disaster — 250+ documents × 7 countries × 4+ languages means 7,000+ files that all need updating when a regulation changes. ISMS CORE solves this with a single-source-of-truth approach: the base policy is authoritative, and the country config is a thin overlay. Update one config file, all affected policies update instantly on next request.

Setting an organisation's country

Country is set per organisation (tenant) by a super admin. All policies served to that organisation render with the correct jurisdiction tokens.

  1. Navigate to Organisations in the admin panel
  2. Edit the organisation and select Country / Regulatory jurisdiction
  3. Save — all subsequent policy renders use the new country config
  4. No restart or rebuild required — configs are baked into the Docker image at build time and cached in memory at first access
