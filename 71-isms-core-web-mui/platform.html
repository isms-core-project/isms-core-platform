Compliance Operations

The core GRC workflow — from policy to evidence to audit readiness. All scoped per project, per organisation.

📁

Projects Workspace

Create named projects that own a curated subset of policies, implementation guides, assessments, gaps, and evidence. Document variables (organisation name, CISO, effective date, legal entity) are auto-substituted on add. WYSIWYG editor with source toggle for in-platform policy editing. Bulk actions, bin/restore, completeness scoring, and SCR checklist tracking — all scoped per project.

📋

Gap & Evidence Management

Full CRUD for compliance gaps: severity, owner, due date, and remediation plan. Evidence tracker with expiry alerts, file download, and verification workflow. Link evidence directly to ISO 27001 control groups. Automated evidence ingested from connectors lands here — no manual copy-paste from external tools.

📊

Live Compliance Dashboard

Real-time compliance scores across all 53 ISO 27001:2022 control groups. Audit readiness composite score (policies + evidence + assessments + open gaps). Section breakdown with bar charts. Control group drill-down with policy, implementation, and evidence links per control.

📈

KPI / Metrics Dashboard

Nine named security KPIs with sparkline trend charts per project. Composite Audit Readiness score (%). Metrics Portfolio view for Super Admins — cross-organisation KPI comparison across all tenants at a glance.

🔍

Full-Text Search

OpenSearch-powered search across all policies, 570+ implementation guides, and 5,200+ extracted requirements. Highlighted results with type and product filters (ISMS / Privacy / Cloud / AI). Semantic search via indexed chunks — find what a control actually says, not just where it appears.

External Document Support

Import existing policies (PDF, DOCX, Markdown) without ISMS CORE formatting. Run the full AI QA analysis against the ISO 27001:2022 reference corpus. See exactly what is missing versus the normative standard — before the auditor does.

Risk & Methodology

Purpose-built tools for ISO 27001 risk treatment, ANSSI EBIOS RM, business continuity, and third-party risk — all integrated with the evidence and gap workflow.

🚨

Risk Register & Heatmap

Project-scoped risk register with a 5×5 probability/impact matrix. Visual heatmap with colour-coded risk zones (green / amber / red). Risk Acceptance and Remediation tracking — action plans, owner assignment, ETA tracking. ITSM push to Jira or ServiceNow for remediation tickets. BSI 200-3 automatic risk calculator with pre-mapped threat codes per ISO section.

🔬

EBIOS RM

Full ANSSI EBIOS Risk Manager methodology: five workshops end-to-end. Workshop 1 (framing) → Workshop 2 (feared events) → Workshop 3 (strategic scenarios) → Workshop 4 (operational scenarios, attack paths) → Workshop 5 (security measures). Integrated with the risk register and remediation tracker. All workshops exportable as a structured risk file.

🏥

Business Impact Analysis (BIA)

RTO / RPO / MTPD capture per business function. Impact scoring across five categories. Recovery priority ranking. Feeds directly into risk register and gap management workflows — ISMS continuity requirements (A.5.29, A.5.30) are linked automatically.

🤝

Third-Party Risk (TPRM)

Vendor register with DORA ICT third-party fields, contract tracking, and risk assessments. Criticality classification, data sharing flags, and remediation tracking. Score and monitor supplier risk in-platform — no separate spreadsheets. DORA Article 28 ICT concentration risk view.

Control Dependency Graph

Interactive Cytoscape.js graph of 229 intra-ISO-27001 control relationships: depends-on, enables, feeds-into. Filter by section, depth, and edge type. Identify which controls are foundational before an audit — fix one, close multiple gaps. Visual and tabular views.

NVD CVE / CPE Explorer

250,000+ CVE entries from NVD, updated via delta feed. Each CVE is cross-enriched with EPSS exploitation probability, CISA KEV known-exploited flag, EUVD flag (present in EU database), and Exploit-DB cross-reference (EDB ID + verified Metasploit module flag). Search and filter by CVSS severity (v3 and v4), EPSS score, year, KEV status, EUVD status, and EDB-only toggle. CPE vendor/product resolution from NVD CPE API. Filtered CVE sets export as CSV-backed audit evidence for ISO 27001 A.8.8.

Exploit-DB

Each entry cross-referenced against NVD CVE by CVE ID — adds edb_id, edb_verified (Metasploit module confirmed), and edb_description fields to every matching CVE. EDB and EDB✓ chips visible in CVE Explorer; Metasploit badge shown in CVE detail panel. "EDB only" toggle in CVE Explorer filters to CVEs with a known public exploit.

AI QA Engine

Four-layer verification against a normative ISO reference corpus. Works on ISMS CORE policies and externally imported documents.

How it works

The QA Engine evaluates any policy or implementation guide against ISO 27001:2022 (and the ISO 27701 / 27018 / 42001 extension packs) using four independent verification layers:

Stage Check What it finds
1 — Existence Document present and parseable Audit proxy: is the control documented at all?
2 — Keyword Coverage ISO normative keyword scan Missing terms required by the standard
3 — Semantic Similarity Vector search against reference corpus Conceptual gaps vs normative text
4 — Claude AI Analysis Gap analysis with reasoning Missing-topic chips, suggested improvements, specific omissions

Reference Corpus

72 JSON seed files, ~13,000 indexed chunks in OpenSearch. Covers ISO 27001/27002/27701/27018/42001/42005, NIST 800-series (800-53, 800-171, 800-63), GDPR, DORA, NIS2, PCI DSS 4.0.1, ENISA guidelines, NSA cybersecurity advisories, CSA CCM, OWASP Top 10, MITRE ATT&CK, CIS Controls, SOC 2, HIPAA, and more.

Crosswalk-Targeted Analysis

QA can be run against a specific framework filter — e.g. validate only the NIST CSF 2.0 requirements that map to this control, or focus the semantic search on DORA-relevant chunks. Uses the 3,433-object crosswalk (44 axes) to scope the corpus automatically.

Model

Claude AI (configurable model via Admin panel — defaults to Claude Sonnet 4.6). API key set once in .env; used only when Stage 4 is triggered. Stages 1–3 run locally with no external API calls.

44 Evidence Connectors

Native connectors ingest live evidence from your stack and map it to ISO 27001:2022 control groups automatically. No ELK stack. No agent to install. Custom Python Docker container for bespoke sources. All 44 connectors are fully routed to per-source OpenSearch indices for real-time analytics.

How evidence flows to controls

1. Connector runs Polls your tool's API on schedule
→
2. Evidence item created Mapped to ISO 27001 control groups (e.g. A.8.8 for CVE, A.5.23 for cloud posture)
→
3. Stored in PostgreSQL + OpenSearch Per-source index for analytics; per-control linkage for compliance
→
4. Control group dashboard Evidence count, status, and age shown on the control — drives audit readiness score
→
5. Gap alert if non-compliant Auto-creates a gap record linked to the control and evidence item

Each connector has a hard-coded control group mapping — for example, Wazuh maps to A.8.15 (logging), A.8.16 (monitoring), and A.8.8 (vulnerability management); Entra ID maps to A.5.15 (access control), A.5.16 (identity management), A.5.17 (authentication), and A.8.5 (privileged access). Evidence is never generic — it is always attached to the specific control it satisfies.

Custom Custom Python Docker container — implement the connector interface, push evidence to any ISO 27001 control group

Each connector maps evidence to one or more ISO 27001:2022 control groups (A.5–A.8), stores results with source reference, classification, and timestamp, and triggers gap alerts on non-compliant findings. Evidence is queryable via the Evidence Explorer and linkable to gaps and risk treatments.

Connector credential security: All API keys and secrets are encrypted at rest using PBKDF2-HMAC-SHA256 with per-tenant salt before storage in PostgreSQL — never stored in plaintext, decrypted only at connector run time.

Per-Source OpenSearch Evidence Indices

Every connector run writes evidence to a dedicated OpenSearch index — evidence-entra-id, evidence-defender, evidence-sentinel, evidence-wazuh, evidence-tenable, evidence-qualys, evidence-crowdstrike, evidence-github, evidence-jira, and 25+ more. All 44 connectors are routed. Source-specific fields are promoted at ingestion — connector-native data (severity, agent count, CVE id, finding type) lands as typed top-level fields, not buried in a JSONB blob.

A wildcard evidence-* index pattern in OpenSearch Dashboards covers all 35 per-source indices for cross-source roll-up analytics. The GET /admin/evidence-indices diagnostic endpoint shows per-index counts and last-updated timestamps.

Access Control & Security

Production-grade auth, multi-tenancy, and full operations visibility built in from day one.

🔐

RBAC & Multi-Organisation

Six roles: Super Admin, Admin, ISMS Manager, Auditor, Control Owner, Viewer. JWT authentication with refresh tokens. Multi-organisation support — Super Admin creates and manages multiple organisations, each with isolated users, projects, and data. Admin panel for user management including cross-org assignment.

🔑

TOTP MFA & MFA Administration

TOTP two-factor authentication for all users — compatible with Google Authenticator, Authy, and any RFC 6238 TOTP app. Enable per-user from System settings. Backup codes provided for device recovery. Platform-wide MFA enforcement toggle in Admin panel. Admin MFA reset — revoke and re-enrol any user's authenticator from the admin panel without requiring user action.

👥

User Groups & Session Management

User group management — create named groups, assign users, and use groups for permission targeting. Full active session management — list all live sessions per user with browser, IP, and last-seen timestamp, revoke individual sessions or all sessions for a user. Session revocation is immediate — JWT refresh tokens are invalidated server-side.

📋

Audit Trail & Operations Log

Three-tab Logs page accessible from the Admin panel: Audit Trail — every user action (login, changes, admin operations) with actor, timestamp, and IP; Feed Runs — scheduled threat intelligence feed execution log with duration, record count, and status; Connector Runs — per-connector evidence pull history with evidence record count, last-run timestamp, and error detail. All events indexed to OpenSearch for search and retention.
