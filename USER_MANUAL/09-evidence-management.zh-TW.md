## 為何證據重要

證據是控制措施有效運作的證明。沒有證據，合規的評鑑分數只是一種主張——有了證據，它才成為可稽核的事實。ISMS CORE 平台管理兩類證據：您手動上傳的證據，以及由連接器自動蒐集的證據。

---

## 證據追蹤器

在側邊欄導覽至 **Evidence → Evidence Tracker**。

追蹤器會顯示您作用中專案的所有證據項目，包含：

- **Control group**——此證據支持哪個控制措施
- **Title**——證據是什麼
- **Source**——來自何處（手動上傳、特定連接器、外部系統）
- **Date collected**——證據何時被蒐集
- **Expiry date**——證據何時需要更新
- **Verification status**——Verified / Pending verification / Expired
- **Freshness indicator**——依存在時間與到期日以顏色標示

---

## 手動新增證據

1. 導覽至 **Evidence → Evidence Tracker**
2. 點選 **New Evidence**
3. 填寫證據表單：

| 欄位 | 說明 |
|-------|-------------|
| **Title** | 描述性名稱（例如「2026 年度滲透測試報告」） |
| **Control group** | 此證據支持哪個控制措施 |
| **Type** | Document / Screenshot / Configuration export / Log / Report / Certificate / Other |
| **Description** | 證據證明了什麼 |
| **Collection date** | 證據何時被蒐集 |
| **Expiry date** | 何時需要更新（若不會過期則留空） |
| **Attachment** | 上傳檔案（PDF、PNG、XLSX 等） |

4. 點選 **Save**

證據項目會出現在追蹤器中，並連結至您指定的控制群組。

## 將證據連結至檢核表項目

證據可附加至特定的檢核表項目，以實現精確的稽核可追溯性：

1. 開啟合規評鑑或 SCR 檢核表
2. 點選任一檢核表項目上的證據圖示
3. 從追蹤器選取既有證據項目，或建立新的項目

當證據項目連結至檢核表項目後，它會出現在項目詳細資料與稽核匯出中——稽核人員可清楚看到哪些證據支持哪一項控制敘述。

---

## 到期與新鮮度

具有到期日的證據項目會自動受到監控：

| 狀態 | 意義 |
|--------|---------|
| **Current** | 到期日在未來（綠色） |
| **Expiring soon** | 30 天內到期（琥珀色） |
| **Expired** | 已過到期日（紅色） |
| **No expiry** | 長青證據——通常是組態匯出，或具有明確效期的憑證 |

儀表板上的 `evidence_freshness` KPI 指標反映現行證據項目的百分比。已過期的證據會被標記，且若超過閾值會觸發健康狀態通知。

## 自動化證據（連接器證據）

平台透過連接器層自動從 44 個整合系統蒐集證據。這些證據會出現在兩個地方：

### 自動化證據分頁（每個控制群組）

每個控制群組詳細資料檢視都有一個 **Automated Evidence** 分頁，顯示該群組最新的連接器證據——每 60 秒更新。項目會顯示：

- 來源連接器（例如「Microsoft Entra ID」、「CrowdStrike Falcon」）
- 蒐集時間戳記
- 分類（存取控制、弱點、組態等）
- 所蒐集內容的摘要文字

### 晉升連接器證據

若要將連接器證據項目移入您正式的證據追蹤器：

1. 在相關控制群組上開啟自動化證據分頁
2. 點選證據項目上的 **Promote**
3. 該項目會出現在您的證據追蹤器中，並預先填入來源、時間戳記與分類

晉升會在您的追蹤器中建立永久紀錄——晉升後的項目不再只是短暫的饋送項目。

---

## 供稽核套件使用的證據

準備稽核時，使用證據追蹤器篩選器來：

1. 依控制群組篩選，以查看特定控制措施的所有證據
2. 檢查缺口——沒有證據的控制群組會被標記
3. 檢查到期——確保在稽核日期前沒有證據失效
4. 將證據清單匯出為 CSV 或 XLSX，供稽核人員套件使用

匯出內容包含檔案附件參照、日期與所有中介資料——稽核人員可依匯出內容要求特定附件。

---

## 驗證流程

證據項目可標記為：

- **Pending verification**——已蒐集但尚未審查
- **Verified**——已由 ISMS 經理或管理員審查並確認為有效
- **Expired**——已過到期日（自動設定）

只有已驗證的證據才會完全計入 `evidence_freshness` KPI 指標。當您確認連接器晉升的證據準確且相關後，請將其標記為已驗證。
