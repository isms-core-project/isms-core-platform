## 什麼是專案？

**Project** 是一個具名的工作區，擁有一組精選的政策、實施指引、評鑑、缺口與證據。它是你 ISMS 的營運單位——你每天處理的一切都在專案內進行。

典型的專案：

- 你的主要 ISO 27001 驗證範圍
- 特定的稽核週期（例如「2026 年監督稽核」）
- 具有自身範圍的組織單位或子公司
- 為 ISO 27701 工作而設的隱私專案

前往側邊欄的 **Projects** 以查看你的專案清單並建立新專案。

---

## 建立專案

1. 點選 **New Project**
2. 輸入專案名稱與選填的描述
3. 選擇產品家族（ISMS、Privacy、Cloud、AI——或全部）
4. 設定文件變數（見下文）——這些會自動套用到你加入專案的所有文件
5. 點選 **Create**

新專案會出現在你的專案清單中。點選它以開啟專案工作區，並將其設為你的作用中專案。

---

## 文件變數

文件變數是組織專屬的權杖，當你把政策文件加入專案時，它們會被替換進文件中。這就是泛用的「Organisation Name shall...」自動變成「Bamboo Tech AG shall...」的方式。

常見的變數包括：

| 變數 | 範例 |
|----------|---------|
| 組織名稱 | Bamboo Tech AG |
| CISO / RSSI 姓名 | Jane Smith |
| DPO 姓名 | Marc Dupont |
| 生效日期 | 2026-05-01 |
| 審查日期 | 2027-05-01 |
| 文件擁有者 | Information Security Team |

變數在建立專案時設定，並可在 **Project Settings** 中更新。更新後，你可以將它們批次重新套用到專案中的所有文件。

## 新增內容到專案

### 新增政策

1. 開啟你的專案並前往 **Policies** 分頁
2. 點選 **Add from Library**
3. 瀏覽或搜尋你想要的政策文件
4. 選取一或多份文件並點選 **Add**

新增政策時，會自動套用文件變數替換——平台會將文件中的所有變數權杖替換為你的專案值。

### 新增實作

前往 **Implementations** 分頁並使用相同的 Add from Library 流程。IMP-UG（面向使用者）與 IMP-TG（技術性）文件會分開列出。

### 批次動作

在 Policies 或 Implementations 分頁中，使用核取方塊欄選取多份文件並執行批次動作：

- **Apply variables**——重新替換文件變數（在更新專案變數後使用）
- **Change status**——將選取的文件移至 draft、review、approved 或 published
- **Move to bin**——將選取的文件軟刪除（可予以還原）

## 文件編輯器

點選專案中的任一文件以開啟 **Document Editor**。編輯器有兩種模式：

### WYSIWYG 模式（預設）

由 TipTap v3 驅動的富文字編輯器。你可以：

- 直接編輯文字——使用格式化工具列設定標題、粗體、斜體、清單與表格
- 新增與編輯表格（格狀表格在儲存時會自動轉換為 GitHub Flavored Markdown）
- 插入圖片（拖放或貼上）

你的變更會自動儲存。文件會保留其原始結構——只有你改動的內容會被修改。

### 原始碼模式

點選 **Source** 切換鈕以切換至原始 Markdown 編輯。這對於精確格式化或批次文字變更很有用。你隨時可以切回 WYSIWYG——平台會正確地呈現你的 Markdown。

> 中繼資料註解區塊（水印）會自動從編輯檢視中移除，以免干擾文件內容。它們會保留在儲存的文件中。

## 文件生命週期（核准流程）

專案中的每份文件都有一個生命週期狀態：

| 狀態 | 意義 |
|-------|---------|
| **Draft** | 進行中——尚未核准 |
| **Review** | 已提交給 ISMS 經理或 Admin 審查 |
| **Approved** | 已審查並核准——可發布 |
| **Published** | 作用中——目前使用中的版本 |

稽核人員可以看到所有狀態。就合規評分而言，只有已發布的文件才被視為「作用中」。

使用文件編輯器中的 **Status** 下拉選單，或透過政策清單中的批次動作來變更文件狀態。

## SCR 檢核表

專案中的每份政策都有一個對應的 **SCR**（自評檢核表）。文件檢視中的 SCR 分頁會顯示該控制群組的檢核表項目。

對每個項目：

1. 設定 **status**——Compliant、Partial、Non-compliant、Not applicable
2. 新增 **comment**，說明你的證據或理由
3. 將證據項目直接**連結**至檢核表項目

完整度評分（已設定狀態的檢核表項目百分比）會以進度列顯示在 SCR 分頁上，並納入專案的整體合規分數。

---

## 專案完整度分數

專案概觀頁面會顯示整體完整度分數——以下項目的加權摘要：

- 政策文件涵蓋率（已新增的預期政策百分比）
- 評鑑完成度（已設定狀態的 SCR 項目百分比）
- 證據附加率（至少有一項證據的檢核表項目百分比）

這是你的主要「我們準備好接受稽核了嗎？」的概覽指標。

---

## 資源回收筒與還原

移至資源回收筒的文件會被軟刪除——它們不會出現在專案檢視中，但不會被永久移除。若要還原：

1. 前往 **Project Settings → Bin**
2. 選取要還原的文件
3. 點選 **Restore**

永久刪除可從資源回收筒檢視執行，且需要 Admin 或 ISMS 經理角色。

---

## 切換作用中專案

一次只能有一個作用中的專案。風險情境、缺口與證據項目都以作用中專案為範圍——切換專案即切換你的工作脈絡。

若要切換：

1. 點選側邊欄中的作用中專案標籤
2. 從清單中選取你想要的專案

或前往 **Projects**，在任何專案上點選 **Set Active**。
