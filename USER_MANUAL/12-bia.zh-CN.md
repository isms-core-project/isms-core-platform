## 概览

**业务影响分析（BIA）** 模块支持 ISO 27001:2022 控制措施 A.5.29（中断期间的信息安全）与 A.5.30（业务连续性的 ICT 准备就绪）。它提供一套结构化的方式，评估中断对业务活动的影响，并建立恢复时间目标。

在侧边栏前往 **Risk & Operations → BIA**，或透过控制措施库中控制措施群组 A.5.29 与 A.5.30 的 BIA 分页访问。

---

## BIA 概念

### 业务活动

BIA 的单位是**业务活动** —— 组织所执行的一项流程、服务或功能。例如：

- 客户订单处理
- 薪资处理
- 财务报告
- 事件响应

每项业务活动都相依于资产（系统、数据、人员），并具备最长可容忍的中断期间。

### 关键恢复时间指标

| 指标 | 定义 |
|--------|-----------|
| **RTO**（恢复时间目标） | 中断后恢复一项业务活动可接受的最长时间 |
| **RPO**（恢复点目标） | 以时间表示的最大可接受数据遗失（例如「不超过 4 小时的数据」） |
| **MTPD**（最长可容忍中断期间） | 该活动在造成不可逆损害之前，可无法提供服务的绝对最长时间 |

其关系为：**RTO ≤ MTPD** 恒成立。若您的 RTO 超过 MTPD，代表您的恢复能力不足，应提出一项缺口。

## 建立 BIA 记录

1. 前往 **Risk & Operations → BIA**
2. 按一下 **New Business Activity**
3. 填写记录：

| 字段 | 描述 |
|-------|-------------|
| **Activity name** | 业务流程或服务的名称 |
| **Owner** | 负责的流程拥有者或团队 |
| **Description** | 该活动做什么，以及为何重要 |
| **Dependencies** | 所需的关键系统、数据存放区或人员 |
| **RTO (hours)** | 恢复时间目标 |
| **RPO (hours)** | 恢复点目标 |
| **MTPD (hours)** | 最长可容忍中断期间 |
| **Financial impact** | 每小时中断的估计财务损失（选填） |
| **Operational impact** | 运营后果分数：1（Minor）至 5（Catastrophic） |
| **Reputational impact** | 声誉后果分数：1（Minor）至 5（Catastrophic） |
| **Regulatory impact** | 法规后果分数：1（Minor）至 5（Catastrophic） |
| **Recovery strategy** | 该活动如何恢复（容错移转、手动因应措施等） |

4. 按一下 **Save**

## 影响评分

平台会从四个影响构面（财务、运营、声誉、法规）计算出整体**影响分数**。影响分数较高的活动代表业务连续性优先顺序较高 —— 它们应具备更紧迫的 RTO 与更稳健的恢复安排。

影响分数会显示在 BIA 清单检视中，并可用于排定哪些活动应优先测试。

---

## 恢复测试

针对每项业务活动，记录恢复测试结果：

1. 开启 BIA 记录并前往 **Recovery Tests** 分页
2. 按一下 **New Test**
3. 记录：
   - 测试日期
   - 测试类型（tabletop exercise / partial failover / full failover）
   - 实际达成的 RTO
   - 实际达成的 RPO
   - 结果（Pass / Fail / Partial）
   - 发现事项与行动

随时间比较实际 RTO／RPO 与目标，可证明您的业务连续性控制措施有效 —— 这是 A.5.29 与 A.5.30 审计的重要证据。

---

## BIA 与控制措施库

BIA 分页内嵌于 A.5.29 与 A.5.30 的控制措施群组详细数据检视中。从控制措施群组检视，您可以看见连结至该控制措施的所有 BIA 记录，并可直接新增，无须离开页面。

---

## BIA 导出

从 BIA 清单检视导出 BIA 登记册，格式为：

- **CSV** —— 所有记录与所有字段，适合试算表分析
- **XLSX** —— 含影响评分与恢复测试历程的格式化试算表
