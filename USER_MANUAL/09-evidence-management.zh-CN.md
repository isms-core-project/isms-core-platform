## 为何证据重要

证据是控制措施有效运作的证明。没有证据，合规的评估分数只是一种主张——有了证据，它才成为可审计的事实。ISMS CORE 平台管理两类证据：您手动上传的证据，以及由连接器自动搜集的证据。

---

## 证据追踪器

在侧边栏导览至 **Evidence → Evidence Tracker**。

追踪器会显示您作用中项目的所有证据项目，包含：

- **Control group**——此证据支持哪个控制措施
- **Title**——证据是什么
- **Source**——来自何处（手动上传、特定连接器、外部系统）
- **Date collected**——证据何时被搜集
- **Expiry date**——证据何时需要更新
- **Verification status**——Verified / Pending verification / Expired
- **Freshness indicator**——依存在时间与到期日以颜色标记

---

## 手动新增证据

1. 导览至 **Evidence → Evidence Tracker**
2. 点选 **New Evidence**
3. 填写证据表单：

| 字段 | 描述 |
|-------|-------------|
| **Title** | 描述性名称（例如「2026 年度渗透测试报告」） |
| **Control group** | 此证据支持哪个控制措施 |
| **Type** | Document / Screenshot / Configuration export / Log / Report / Certificate / Other |
| **Description** | 证据证明了什么 |
| **Collection date** | 证据何时被搜集 |
| **Expiry date** | 何时需要更新（若不会过期则留空） |
| **Attachment** | 上传档案（PDF、PNG、XLSX 等） |

4. 点选 **Save**

证据项目会出现在追踪器中，并连结至您指定的控制群组。

---

## 将证据连结至检查表项目

证据可附加至特定的检查表项目，以实现精确的审计可追溯性：

1. 开启合规评估或 SCR 检查表
2. 点选任一检查表项目上的证据图示
3. 从追踪器选取既有证据项目，或建立新的项目

当证据项目连结至检查表项目后，它会出现在项目详细数据与审计导出中——审计人员可清楚看到哪些证据支持哪一项控制叙述。

---

## 到期与新鲜度

具有到期日的证据项目会自动受到监控：

| 状态 | 意义 |
|--------|---------|
| **Current** | 到期日在未来（绿色） |
| **Expiring soon** | 30 天内到期（琥珀色） |
| **Expired** | 已过到期日（红色） |
| **No expiry** | 长青证据——通常是配置导出，或具有明确效期的凭证 |

仪表板上的 `evidence_freshness` KPI 指标反映现行证据项目的百分比。已过期的证据会被标记，且若超过阈值会触发健康状态通知。

## 自动化证据（连接器证据）

平台透过连接器层自动从 44 个整合系统搜集证据。这些证据会出现在两个地方：

### 自动化证据分页（每个控制群组）

每个控制群组详细数据检视都有一个 **Automated Evidence** 分页，显示该群组最新的连接器证据——每 60 秒更新。项目会显示：

- 来源连接器（例如「Microsoft Entra ID」、「CrowdStrike Falcon」）
- 搜集时间戳记
- 分类（访问控制、漏洞、配置等）
- 所搜集内容的摘要文本

### 晋升连接器证据

若要将连接器证据项目移入您正式的证据追踪器：

1. 在相关控制群组上开启自动化证据分页
2. 点选证据项目上的 **Promote**
3. 该项目会出现在您的证据追踪器中，并预先填入来源、时间戳记与分类

晋升会在您的追踪器中建立永久记录——晋升后的项目不再只是短暂的馈送项目。

---

## 供审计套件使用的证据

准备审计时，使用证据追踪器筛选器来：

1. 依控制群组筛选，以查看特定控制措施的所有证据
2. 检查缺口——没有证据的控制群组会被标记
3. 检查到期——确保在审计日期前没有证据失效
4. 将证据清单导出为 CSV 或 XLSX，供审计人员套件使用

导出内容包含档案附件参照、日期与所有中介数据——审计人员可依导出内容要求特定附件。

---

## 验证流程

证据项目可标记为：

- **Pending verification**——已搜集但尚未审查
- **Verified**——已由 ISMS 经理或管理员审查并确认为有效
- **Expired**——已过到期日（自动设置）

只有已验证的证据才会完全计入 `evidence_freshness` KPI 指标。当您确认连接器晋升的证据准确且相关后，请将其标记为已验证。
