## 什么是缺口？

缺口是一项经记录的缺失——一个未实作、部分实作，或缺少证据的控制措施。缺口是您 ISMS 的主要待办事项：它们代表在您的控制措施完全有效之前必须完成的工作。

ISMS CORE 中的缺口绑定于您的作用中项目。在侧边栏导览至 **Risk & Operations → Gaps**。

---

## 建立缺口

缺口可透过两种方式建立：

### 从检查表项目

在评估控制措施并将项目标记为不合规或部分合规时，可直接从检查表项目点选 **Create Gap**。缺口会预先填入控制 ID、项目参照与您的备注。

### 手动建立

1. 导览至 **Risk & Operations → Gaps**
2. 点选 **New Gap**
3. 填写缺口表单：

| 字段 | 描述 |
|-------|-------------|
| **Title** | 缺口的简短描述（例如「管理员账户未启用 MFA」） |
| **Control group** | 此缺口属于哪个 ISO 控制群组 |
| **Severity** | Critical / High / Medium / Low |
| **Owner** | 负责矫正的用户或团队 |
| **Due date** | 目标矫正日期（SLA） |
| **Description** | 缺口的完整描述与背景 |
| **Source** | 缺口如何被识别（内部审计、渗透测试、评估、连接器等） |

## 缺口生命周期

每个缺口都会经历既定的生命周期：

```
Open → In Progress → Resolved → Closed
              ↓
         Risk Accepted（若未进行矫正）
```

| 状态 | 意义 |
|-------|---------|
| **Open** | 缺口已识别，尚未著手处理 |
| **In Progress** | 矫正行动进行中 |
| **Resolved** | 矫正完成——等待验证 |
| **Closed** | 已验证并关闭——证据已确认 |
| **Risk Accepted** | 组织已正式将此缺口接受为残余风险 |

随著工作推进更新状态。只有 ISMS 经理与管理员角色可以关闭缺口或接受缺口风险。

## BSI 200-3 风险计算器

针对每个缺口，平台提供以 BSI 200-3 风险模型为基础的自动风险计算器。当您选取控制群组并设置严重性后，计算器会预先填入：

- **Threat code**——此 ISO 控制章节对应的 BSI 威胁类别
- **Likelihood**——由控制类型与威胁类别预先对应
- **Impact**——由您选取的严重性预先对应
- **Risk level**——可能性 × 影响，显示为低／中／高／极高

若您的评估不同，可以覆写预先对应的值。

## 矫正追踪

对于正在矫正的缺口，可从缺口详细数据检视新增 **Action Plan**：

| 字段 | 描述 |
|-------|-------------|
| **Action** | 需要完成的事项 |
| **Owner** | 谁负责这项特定行动 |
| **ETA** | 目标完成日期 |
| **Effort** | 预估工作量（天数或故事点） |
| **Cost** | 预估成本（选填） |
| **Progress** | 完成百分比（0–100） |

可将多个行动项目加入单一缺口，以代表分阶段的矫正方式。

### ITSM 整合

若您的组织使用 Jira 或 ServiceNow，可直接从缺口详细数据检视将行动计划项目推送为工单。点选 **Push to Jira** 或 **Push to ServiceNow** 以建立工单。推送具幂等性——再次点选会更新既有工单，而非建立重复项。

工单状态（开启、进行中、完成）会依计划自动同步回平台。

## SLA 监控

具有到期日的缺口会受到 SLA 合规监控。缺口清单会显示：

- **On track**——到期日在未来
- **Due soon**——7 天内到期
- **Overdue**——已过到期日但未解决或关闭

KPI 仪表板指标 `gap_closure_rate` 与 `remediation_overdue` 衍生自您的缺口 SLA 数据。

---

## 风险接受

若您的组织决定不矫正某个缺口（接受残余风险），请将缺口状态变更为 **Risk Accepted** 并记录：

- 业务理由
- 谁批准了风险接受（签核拥有者）
- 审查日期（何时应重新考虑此接受）

已接受风险的缺口会从逾期 SLA 计算中排除，但仍会显示于缺口清单与审计导出中。

---

## 缺口报告

从缺口清单：

- **Filter** 依严重性、状态、拥有者、控制群组或日期范围
- **Export** 为 CSV 或 XLSX
- **Group by** 依控制群组或拥有者以取得摘要检视

导出内容包含所有缺口字段、行动计划项目与目前状态——适合管理报告或审计证据。

---

## 缺口与风险登录表

重大缺口可升级至风险登录表，成为正式的风险情境。从缺口详细数据检视点选 **Escalate to Risk Register** 以建立连结的风险情境。缺口维持开启，并连结至风险记录以实现完整可追溯性。

关于风险情境如何管理，请见[风险登录表](11-risk-register.zh-CN.md)。
