## 什麼是缺口？

缺口是一項經記錄的缺失——一個未實作、部分實作，或缺少證據的控制措施。缺口是您 ISMS 的主要待辦事項：它們代表在您的控制措施完全有效之前必須完成的工作。

ISMS CORE 中的缺口綁定於您的作用中專案。在側邊欄導覽至 **Risk & Operations → Gaps**。

---

## 建立缺口

缺口可透過兩種方式建立：

### 從檢核表項目

在評鑑控制措施並將項目標記為不合規或部分合規時，可直接從檢核表項目點選 **Create Gap**。缺口會預先填入控制 ID、項目參照與您的備註。

### 手動建立

1. 導覽至 **Risk & Operations → Gaps**
2. 點選 **New Gap**
3. 填寫缺口表單：

| 欄位 | 說明 |
|-------|-------------|
| **Title** | 缺口的簡短說明（例如「管理員帳戶未啟用 MFA」） |
| **Control group** | 此缺口屬於哪個 ISO 控制群組 |
| **Severity** | Critical / High / Medium / Low |
| **Owner** | 負責矯正的使用者或團隊 |
| **Due date** | 目標矯正日期（SLA） |
| **Description** | 缺口的完整描述與背景 |
| **Source** | 缺口如何被識別（內部稽核、滲透測試、評鑑、連接器等） |

## 缺口生命週期

每個缺口都會經歷既定的生命週期：

```
Open → In Progress → Resolved → Closed
              ↓
         Risk Accepted（若未進行矯正）
```

| 狀態 | 意義 |
|-------|---------|
| **Open** | 缺口已識別，尚未著手處理 |
| **In Progress** | 矯正行動進行中 |
| **Resolved** | 矯正完成——等待驗證 |
| **Closed** | 已驗證並關閉——證據已確認 |
| **Risk Accepted** | 組織已正式將此缺口接受為殘餘風險 |

隨著工作推進更新狀態。只有 ISMS 經理與管理員角色可以關閉缺口或接受缺口風險。

## BSI 200-3 風險計算器

針對每個缺口，平台提供以 BSI 200-3 風險模型為基礎的自動風險計算器。當您選取控制群組並設定嚴重性後，計算器會預先填入：

- **Threat code**——此 ISO 控制章節對應的 BSI 威脅類別
- **Likelihood**——由控制類型與威脅類別預先對應
- **Impact**——由您選取的嚴重性預先對應
- **Risk level**——可能性 × 衝擊，顯示為低／中／高／極高

若您的評鑑不同，可以覆寫預先對應的值。

## 矯正追蹤

對於正在矯正的缺口，可從缺口詳細資料檢視新增 **Action Plan**：

| 欄位 | 說明 |
|-------|-------------|
| **Action** | 需要完成的事項 |
| **Owner** | 誰負責這項特定行動 |
| **ETA** | 目標完成日期 |
| **Effort** | 預估工作量（天數或故事點） |
| **Cost** | 預估成本（選填） |
| **Progress** | 完成百分比（0–100） |

可將多個行動項目加入單一缺口，以代表分階段的矯正方式。

### ITSM 整合

若您的組織使用 Jira 或 ServiceNow，可直接從缺口詳細資料檢視將行動計畫項目推送為工單。點選 **Push to Jira** 或 **Push to ServiceNow** 以建立工單。推送具冪等性——再次點選會更新既有工單，而非建立重複項。

工單狀態（開啟、進行中、完成）會依排程自動同步回平台。

## SLA 監控

具有到期日的缺口會受到 SLA 合規監控。缺口清單會顯示：

- **On track**——到期日在未來
- **Due soon**——7 天內到期
- **Overdue**——已過到期日但未解決或關閉

KPI 儀表板指標 `gap_closure_rate` 與 `remediation_overdue` 衍生自您的缺口 SLA 資料。

---

## 風險接受

若您的組織決定不矯正某個缺口（接受殘餘風險），請將缺口狀態變更為 **Risk Accepted** 並記錄：

- 業務理由
- 誰核准了風險接受（簽核擁有者）
- 審查日期（何時應重新考慮此接受）

已接受風險的缺口會從逾期 SLA 計算中排除，但仍會顯示於缺口清單與稽核匯出中。

---

## 缺口報告

從缺口清單：

- **Filter** 依嚴重性、狀態、擁有者、控制群組或日期範圍
- **Export** 為 CSV 或 XLSX
- **Group by** 依控制群組或擁有者以取得摘要檢視

匯出內容包含所有缺口欄位、行動計畫項目與目前狀態——適合管理報告或稽核證據。

---

## 缺口與風險登錄表

重大缺口可升級至風險登錄表，成為正式的風險情境。從缺口詳細資料檢視點選 **Escalate to Risk Register** 以建立連結的風險情境。缺口維持開啟，並連結至風險紀錄以實現完整可追溯性。

關於風險情境如何管理，請見[風險登錄表](11-risk-register.zh-TW.md)。
