## 概觀

**業務衝擊分析（BIA）** 模組支援 ISO 27001:2022 控制措施 A.5.29（中斷期間的資訊安全）與 A.5.30（營運持續的 ICT 準備就緒）。它提供一套結構化的方式，評估中斷對業務活動的衝擊，並建立復原時間目標。

在側邊欄前往 **Risk & Operations → BIA**，或透過控制措施庫中控制措施群組 A.5.29 與 A.5.30 的 BIA 分頁存取。

---

## BIA 概念

### 業務活動

BIA 的單位是**業務活動** —— 組織所執行的一項流程、服務或功能。例如：

- 客戶訂單處理
- 薪資處理
- 財務報告
- 事件應變

每項業務活動都相依於資產（系統、資料、人員），並具備最長可容忍的中斷期間。

### 關鍵復原時間指標

| 指標 | 定義 |
|--------|-----------|
| **RTO**（復原時間目標） | 中斷後復原一項業務活動可接受的最長時間 |
| **RPO**（復原點目標） | 以時間表示的最大可接受資料遺失（例如「不超過 4 小時的資料」） |
| **MTPD**（最長可容忍中斷期間） | 該活動在造成不可逆損害之前，可無法提供服務的絕對最長時間 |

其關係為：**RTO ≤ MTPD** 恆成立。若您的 RTO 超過 MTPD，代表您的復原能力不足，應提出一項缺口。

## 建立 BIA 記錄

1. 前往 **Risk & Operations → BIA**
2. 按一下 **New Business Activity**
3. 填寫記錄：

| 欄位 | 說明 |
|-------|-------------|
| **Activity name** | 業務流程或服務的名稱 |
| **Owner** | 負責的流程擁有者或團隊 |
| **Description** | 該活動做什麼，以及為何重要 |
| **Dependencies** | 所需的關鍵系統、資料存放區或人員 |
| **RTO (hours)** | 復原時間目標 |
| **RPO (hours)** | 復原點目標 |
| **MTPD (hours)** | 最長可容忍中斷期間 |
| **Financial impact** | 每小時中斷的估計財務損失（選填） |
| **Operational impact** | 營運後果分數：1（Minor）至 5（Catastrophic） |
| **Reputational impact** | 聲譽後果分數：1（Minor）至 5（Catastrophic） |
| **Regulatory impact** | 法規後果分數：1（Minor）至 5（Catastrophic） |
| **Recovery strategy** | 該活動如何復原（容錯移轉、手動因應措施等） |

4. 按一下 **Save**

## 衝擊評分

平台會從四個衝擊構面（財務、營運、聲譽、法規）計算出整體**衝擊分數**。衝擊分數較高的活動代表營運持續優先順序較高 —— 它們應具備更緊迫的 RTO 與更穩健的復原安排。

衝擊分數會顯示在 BIA 清單檢視中，並可用於排定哪些活動應優先測試。

---

## 復原測試

針對每項業務活動，記錄復原測試結果：

1. 開啟 BIA 記錄並前往 **Recovery Tests** 分頁
2. 按一下 **New Test**
3. 記錄：
   - 測試日期
   - 測試類型（tabletop exercise / partial failover / full failover）
   - 實際達成的 RTO
   - 實際達成的 RPO
   - 結果（Pass / Fail / Partial）
   - 發現事項與行動

隨時間比較實際 RTO／RPO 與目標，可證明您的營運持續控制措施有效 —— 這是 A.5.29 與 A.5.30 稽核的重要證據。

---

## BIA 與控制措施庫

BIA 分頁內嵌於 A.5.29 與 A.5.30 的控制措施群組詳細資料檢視中。從控制措施群組檢視，您可以看見連結至該控制措施的所有 BIA 記錄，並可直接新增，無須離開頁面。

---

## BIA 匯出

從 BIA 清單檢視匯出 BIA 登記冊，格式為：

- **CSV** —— 所有記錄與所有欄位，適合試算表分析
- **XLSX** —— 含衝擊評分與復原測試歷程的格式化試算表
