## Purpose of This Guide

This guide provides the **templates, schemas, and reference structures** for AI transparency and communication — including user documentation template, transparency notice template, external incident notification template, interested party information register schema, and external enquiry register schema.

**Audience**: AI Governance Officer, AI System Owners, Legal, Communications.

---

## 1. User Documentation Template (A.8.2)

Complete one user documentation document per in-scope AI system (or per significant version where content materially changes). Published to users before deployment.

---

```
AI SYSTEM USER DOCUMENTATION
System: [AI System Name] | Version: [X.X] | Date: [YYYY-MM-DD]
Document ID: UDOC-[System-ID]-v[X.X]
Maintained By: [AI System Owner Name]

WHAT THIS SYSTEM DOES
[Plain-language explanation — 2–4 sentences. What the AI system is for, what 
kind of outputs it produces, how it contributes to the workflow.]

INTENDED USE
This system is designed for: [Specific uses]
This system is intended to be used by: [User categories; any competency requirements]
This system should only be used when: [Conditions for valid use]

WHAT THIS SYSTEM SHOULD NOT BE USED FOR
Out of scope: [Uses the system was not designed for]
Prohibited: [Uses explicitly forbidden — including any that could cause harm]

WHAT THIS SYSTEM'S OUTPUTS MEAN
[Explain what outputs are produced and how to interpret them.
If the system produces scores, classifications, or rankings: explain what they mean.
If outputs are probabilistic: explain what confidence levels indicate.]

PERFORMANCE AND LIMITATIONS
What it does well: [Brief statement of where the system performs reliably]
Known limitations:
1. [Limitation 1 — specific condition or input type where outputs are less reliable]
2. [Limitation 2]
3. [Edge case or failure mode users should know about]

HUMAN OVERSIGHT REQUIREMENTS
[Explain what human review is required before acting on AI outputs.
Be specific: "A qualified [role] must review the AI recommendation before 
[action X] is taken" is more useful than "use with appropriate oversight".]

HOW TO USE THIS SYSTEM RESPONSIBLY
1. [Specific responsible use instruction]
2. [Second instruction]
3. [Third instruction]

HOW TO REPORT A CONCERN
If you observe unexpected outputs, suspect misuse, or have any concern about 
this AI system: [Contact method / Channel reference]
Response time commitment: [Within X business days]

CONTACT
For questions about this AI system: [AI System Owner contact details]
For AI governance questions: [AI Governance Officer contact details]

Version history: [Track major documentation updates]
```

## 2. Transparency Notice Template (A.8.2 / EU AI Act Article 50)

Use for customer-facing and public-facing AI interactions. Adapt to the specific interaction type.

---

```
[ORGANISATION] — AI NOTICE

[Short form — for UI display, banner, or pre-interaction notification]

This [service / feature / interaction] uses artificial intelligence.

[Describe in one sentence what the AI does here — e.g., "Our AI assistant 
analyses your query and provides recommendations based on [description]."]

[If AI influences decisions about the user:]
AI may [inform / contribute to] decisions about your [claim / application / 
request]. You have the right to [request human review / contact us at [email]].

[If generative AI content:]
Some [responses / content] on this page [are / may be] generated by AI.

[Contact for questions about AI use:]
Questions? Contact: [email or link]

[Long form — for privacy notice or product documentation]

USE OF ARTIFICIAL INTELLIGENCE

[Organisation] uses AI technology in [this product / this feature / this service].

How AI is used here:
[Detailed explanation of what AI does; what data is used as input; what kind
of output it produces; how that output is used]

What this means for you:
[How AI affects the user's experience or decisions that may affect them]

Human oversight:
[Whether and how human review is applied to AI outputs]

Your rights:
[Right to know AI is being used — provided in this notice]
[Right to request human review (if applicable)]
[Right to object (if applicable)]
[How to exercise these rights]

Questions: [Contact]
```

## 3. External Incident Notification Template (A.8.4)

Use as the basis for external incident notifications. Adapt to the recipient and regulatory format required.

---

```
AI INCIDENT NOTIFICATION

To: [Regulatory authority / Customer / Affected individual / Partner]
From: [AI Governance Officer / Legal — Organisation name]
Date: [YYYY-MM-DD]
Reference: [Incident ID]
Subject: Notification of AI System Incident — [Brief description]

1. AI SYSTEM AFFECTED
   System name: [Name]
   System version: [Version]
   Purpose: [Brief description of what the system does]
   
2. INCIDENT DESCRIPTION
   Date and time of incident (or when detected): [YYYY-MM-DD; time if known]
   Duration: [If known]
   Nature of incident: [What occurred — factual description]
   
3. IMPACT
   Number and categories of affected individuals: [Estimate or known count]
   Nature of impact on affected individuals: [What harm or adverse effect occurred]
   Severity: [Assessment of severity]
   
4. IMMEDIATE STEPS TAKEN
   [What [Organisation] has done immediately to contain or mitigate the incident]
   
5. INVESTIGATION STATUS
   [Current status of investigation; expected timeline for more information]
   
6. ONGOING MEASURES
   [What measures are being taken to prevent recurrence]
   
7. CONTACT
   For enquiries regarding this incident:
   [Name, role, email, phone]
   
[This notification is provided in accordance with [applicable legal obligation].
[Organisation] will provide further updates as the investigation progresses.]
```

## 4. Interested Party Information Register Schema (A.8.5)

Per-AI-system register documenting what information is provided to each interested party category. Maintained by AI Governance Officer.

| Field | Type | Description |
|-------|------|-------------|
| AI System ID | Text | Reference to Resource Register |
| AI System Name | Text | |
| Interested Party Category | Enum | Direct users / Affected individuals / Customers / Partners / Regulators / Public / Auditors |
| Information Determined Appropriate | Text | What information is provided to this party category |
| Format / Delivery Channel | Text | How information is provided (documentation / website / notice / API / on request) |
| Update Trigger | Text | What triggers a review of this information (system update / regulation change / annual) |
| Sensitivity Assessment | Text | Whether any content is commercially or security-sensitive (and if so, what is redacted) |
| Legal Obligation | Text | Applicable legal obligation for this disclosure (if any) |
| Last Updated | Date | |
| Next Review Date | Date | |
| Reviewed By | Text | AI Governance Officer |

## 5. External Enquiry Register Schema (A.8.3)

Tracks all external requests for AI system information.

| Field | Type | Description |
|-------|------|-------------|
| Enquiry ID | Text | Unique reference (e.g., ENQ-2026-001) |
| Date Received | Date | |
| Enquirer | Text | Name, organisation, or type (anonymous / member of public / regulator / customer) |
| Enquiry Type | Enum | Regulatory request / Customer enquiry / Civil society / Public / Media / Other |
| AI System Referenced | Text | If system-specific |
| Subject of Enquiry | Text | Summary of what was asked |
| Assigned To | Text | AI Governance Officer / Legal |
| Response Due Date | Date | Per applicable obligation or standard SLA |
| Response Date | Date | Date response sent |
| Response Summary | Text | Summary of response provided |
| Regulatory Obligation | Text | If applicable: specific regulatory provision and deadline |
| Status | Enum | Open / Responded / Escalated / Closed |
